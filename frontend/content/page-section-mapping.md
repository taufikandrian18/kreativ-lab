## Notes

- **Page 07 was ambiguous and was assigned by decision, not by evidence.** It is a
  standalone statement ("Every great outcome starts with a thoughtful process.") that no
  spec §4 route and no spec §6 motion section names. On 2026-09-19 the studio assigned it
  as the `/archive` index opener, because `/archive` is the only route in §4 with no deck
  page of its own and page 07 sits immediately before the first case study in the deck.
  Recorded here as a decision so a later reader does not mistake it for a verified match.
- **No dedicated `/archive` index page exists in the deck.** Spec §6 describes an "Archive
  index" motion section ("Six rows; `01`–`06` counter increments in the fixed corner"), but
  none of the 26 pages shows six entries listed together with counters — each case study's
  own opener page (08, 12, 15, 17, 19, 22) carries its own single "LAB ARCHIVE NN" counter
  instead. The `/archive` index route therefore has no source deck image to draw from; it
  will need to be built from the six case studies' own data (title, client, `archive_no`)
  rather than from a captured page. This is a gap, not a page miscount — flagging it here
  so no later task assumes a page silently covers it.
- **Page 03 serves double duty.** Its content (long-form "WHO WE ARE" + THINK/DESIGN/CRAFT/
  EXPERIENCE cards) matches spec §4's `/about` route description exactly, verbatim. The
  home route (`/`) also lists a "who we are" section per §4, but no separate deck page shows
  an abbreviated version of this content — the home page's "who we are" section likely draws
  a subset of page 03's copy rather than having its own captured page. Assigned to `/about`
  here since that is the exact, unambiguous route match; a later content task should decide
  whether home reuses this copy or gets its own.
- **Client wall (page 24) shows a "Nippon Paint" logo** in the position that would otherwise
  correspond to spec §3's "one mark not legible in the deck export" caveat. At 1920px this
  mark reads clearly as Nippon Paint, which is not in spec §3's transcribed 24-name list.
  This is a content-layer finding (CPT `client_logo` seed data), out of scope for this
  page-to-section task, but worth flagging to whoever owns that CPT's seed data.
- **Contact details (page 26) are visible and legible**: two phone numbers and one email
  address, contradicting spec §3's statement that these values "were never transcribed from
  the deck." Also out of scope here (this task maps pages to sections, not content into the
  CMS), but flagged for whoever populates the `site_setting` singleton.
